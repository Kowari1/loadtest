4. Сравните количество POST-запросов (HTTP) и количество входящих сообщений в Kafka — есть ли расхождения? О чём это может говорить?

HTTP POST выполнялся со скоростью примерно 4,8–5,2 запроса/с, что соответствует целевой нагрузке 5 TPS.

На Kafka были рассмотрены следующие показатели:

Producer Record Send Rate:

rate(kafka_producer_record_send_total[1m])

а также Kafka Produce/Request metrics.

При этом значения Kafka существенно ниже HTTP TPS, например kafka_producer_record_send_rate в отдельный момент составлял около 0,07 записи/с.

На первый взгляд это выглядит как расхождение, однако напрямую сравнивать эти показатели некорректно из-за архитектуры тестируемого приложения.

Один HTTP POST содержит JSON, внутри которого находится 100 ID. POST не отправляет каждую из этих 100 сущностей непосредственно в Kafka отдельным HTTP-запросом. Приложение сначала накапливает данные, после чего отдельный поток выполняет пакетную отправку в Kafka.
Кроме того, GET работает независимо от этого механизма: он может обращаться к приложению, пока пакет из 100 элементов ещё не сформирован.

Поэтому небольшое количество Kafka producer records относительно количества HTTP POST само по себе не означает потерю сообщений.

Дополнительным подтверждением является:

Consumer Lag = 0
Producer record errors = 0
Producer record retries = 0

Также Kafka Producer показывает:

record_error_total = 0
record_retry_total = 0
buffer_exhausted_total = 0

Вывод: прямого соответствия 1 HTTP POST = 1 Kafka record в данной архитектуре нет. Наблюдаемое расхождение объясняется пакетной обработкой данных и асинхронной отправкой в Kafka. Признаков потери сообщений или перегрузки Kafka при этом не обнаружено.
